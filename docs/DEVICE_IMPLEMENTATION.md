# PW2 设备端实施记录

采用已确认的 C 常驻增量采集 + Rust 按需 worker。默认只采集，不主动开启 Wi-Fi、不阻止休眠、不接管原生阅读器。

## 验收顺序

- [ ] PW2 / 5.12.2.1.1 root 与启动环境自检。
- [x] 采集器的日志轮换、半行、重启、封存、配额和事件状态合成测试；含本机日志形状的 ReaderBooklet 生命周期。
- [x] Rust 解析、来源、时钟、账本、续期和防重放离线测试。
- [x] ARM 交叉构建候选（experimental-static-musl）。
- [ ] 最小真机 ELF、文件和 TLS 自检。
- [ ] 真机睡眠、USB、翻页与耗电验证。
- [ ] 新增真实阅读的同书连续会话、多小时、跨日入账验证。
- [ ] 一周独立运行验证后才发布为正式支持。

## 现有数据

原 Mac 实例及其 旧试传待核验记录继续保留，不重传、不迁入新的空账本。设备端从交接后的新开书窗口开始。上传权交接必须通过 Mac fence 保证单一写入者；导入和只读复核继续可用。

## 真实状态

2026-11-02：读取 USB version.txt 确认为 5.12.2.1.1，未发现越狱或扩展安装标记。官方 KindleBreak 归档已按文档 MD5 和本地 SHA256 校验，暂存于本机私有准备目录；需用户在设备上触发并接回后核验。不能把准备文件完成等同于设备已越狱、程序已部署或入账已通过。

## 软件核验与未完成边界

- Python层、C真实进程合成测试、Rust worker和原日志适配器分别验证；不向微信读书发真实写请求。
- 保留日志的只读交叉解析与原 Mac source keys/秒数一致，重复导入不新增。此类本机测试不证明设备性能。
- 两个 C组件和Rust worker已交叉编译为ARM32静态ELF；候选包标记device_tested=false、upload_enabled=false。
- 原 Mac运行代码已更新且原有账本数量不变，未执行上传权交接或设备专用登录。
- KindleBreak材料仅已暂存校验；没有成功日志或root探针前，不能声称已越狱/已安装/自动上传已可用。
- 超过4MiB的离线或未核验积压将保守阻断解析；正常已确认队列支持安全compact，未确认和未匹配的数据不清理。

## 最终本机软件验证（2026-11-02）

69 项 Python 测试、19 项 C 真实进程合成测试、43 项 Rust worker 测试和 9 项 Rust 日志适配器测试全部通过，共 140 项。C 通过-Werror编译与静态分析；Rust格式检查通过。自启动/进程重启的状态重放已通过FIFO握手回归，不依赖Upstart是否重启适配器。上述结果均不是PW2真机或微信读书真实入账验收。
