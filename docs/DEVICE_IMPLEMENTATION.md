# PW2 设备端实施记录

采用已确认的 C 常驻增量采集 + Rust 按需 worker。默认只采集，不主动开启 Wi-Fi、不阻止休眠、不接管原生阅读器。

## 验收顺序

- [x] PW2 / 5.12.2.1.1 root、Upstart、LIPC 与启动环境探针。
- [x] 采集器的日志轮换、半行、重启、封存、配额和事件状态合成测试；含本机日志形状的 ReaderBooklet 生命周期。
- [x] Rust 解析、来源、时钟、账本、续期和防重放离线测试。
- [x] ARM 交叉构建候选（experimental-static-musl）。
- [x] 最小 ARM worker 真机 ELF 与私有文件/SQLite 自检（无网络）。
- [ ] 真机 DNS / TLS 自检。
- [ ] 真机睡眠、USB、翻页与耗电验证。
- [ ] 新增真实阅读的同书连续会话、多小时、跨日入账验证。
- [ ] 一周独立运行验证后才发布为正式支持。

## 现有数据

原 Mac 实例及其 旧试传待核验记录继续保留，不重传、不迁入新的空账本。设备端从交接后的新开书窗口开始。上传权交接必须通过 Mac fence 保证单一写入者；导入和只读复核继续可用。

## 真实状态

2026-11-02：KindleBreak 成功日志已核验，用户完成 legacy hotfix 1.16N 与 MRPI/KUAL 安装。KUAL 导出的 root 探针确认 PW2 / B0D4、5.12.2.1.1、ARMv7、Linux 3.0.35-lab126、glibc 2.20、Upstart/LIPC 可用，root 文件系统为只读。候选静态 Rust worker 在本台运行，私有文件/SQLite 自检成功，未联网且未生成验收证书。

本台 `/var/local` 总量 63,461 KiB、首次探针空闲 42,322 KiB，因此原先 64 MiB 空闲准入和 16 MiB 队列/账本上限不适用。PW2 配置调整为原始队列 4 MiB、账本 4 MiB、例行事务 4 MiB 加 64 KiB 开销，并保留至少 20 MiB 系统空间；安装检查还计入组件暂存和旧版本恢复副本。空间不足时阻断，不删除亚马逊数据或未确认记录。

## 软件核验与未完成边界

- Python层、C真实进程合成测试、Rust worker和原日志适配器分别验证；不向微信读书发真实写请求。
- 保留日志的只读交叉解析与原 Mac source keys/秒数一致，重复导入不新增。此类本机测试不证明设备性能。
- 两个 C组件和Rust worker已交叉编译为ARM32静态ELF；候选包标记device_tested=false、upload_enabled=false。
- 原 Mac运行代码已更新且原有账本数量不变，未执行上传权交接或设备专用登录。
- 已完成越狱与无网络 root/worker 自检；常驻服务、性能、休眠/USB循环及账号上传仍须按清单逐项验收。Hotfix 本身不是 OTA 防护，首次联网前另行核验适用的可逆防护。
- 超过4MiB的离线或未核验积压将保守阻断解析；正常已确认队列支持安全compact，未确认和未匹配的数据不清理。

## 本机软件验证（2026-11-02）

本轮 76 项 Python 测试、8 项安装事务/容量测试、20 项 C 真实进程与空间测试、58 项 Rust worker 测试通过；另对大 checkpoint 不占用 worker 回滚预算的补修进行了针对性 C 测试。9 项未改动的 Rust 日志适配器测试沿用前次通过结果。C 通过 -Werror 编译与静态分析，Rust 格式检查通过。自启动/进程重启的状态重放已通过 FIFO 握手回归，不依赖 Upstart 是否重启适配器。上述结果均不是 PW2 翻页、耗电或微信读书真实入账验收。
