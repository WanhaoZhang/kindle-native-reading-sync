# 网页导入版实测复现

使用 PW2、固件 5.12.2.1.1 和 Mac，保留原生阅读器。项目可单独运行，设备端项目的越狱、ARM 构建和无 Mac 直传另有[完整记录](https://github.com/WanhaoZhang/kindle-device-autosync/blob/main/docs/PW2_REPRODUCTION.md)。

## 先验证日志

1. 按 [README](../README.md#安装macos) 运行 `./setup.sh` 与 `./启动阅读同步.command`，打开 **http://127.0.0.1:8765/**。
2. 原生阅读 3–5 分钟并翻几页，退回书库。在 Kindle 首页搜索英文半角 `;dm`，等待约 30 秒，然后接 Mac。若 Kindle 已拔线，直接执行阅读与 `;dm` 后再接，省掉一次连接。
3. 点网页的导入按钮。保持原实例目录，程序复制日志、副文件和元数据，再按书、日期、小时生成报告。记录试读的书名和时段，核对完整开关书、阅读模型 `counted` 增量和 UTC/本地小时证据。实测 3–5 分钟窗口恢复出约 4 分 38 秒，日志以前的已轮换数据无法从副文件累计量推算。
4. 采集和上传可以分开。若想保留日级历史，先及时导出并导入本机，之后按需查看或处理。日志按容量轮换，不能承诺等一个月仍保留完整历史。

## 再验证一次真实写入

1. 在本机网页生成二维码，微信扫描并手机确认。在同一账号查目标书籍。若书城和个人上传书都存在，比较作者、版次、书籍 ID 和原有进度后选择一个准确版本。
2. 记下微信读书中这本书的累计、目标日期总量和原阅读位置。选择一段未提交的真实新阅读，生成预览并检查书名、日期、用时。已有书架记录、同名版本或个人导入文件的情况见 [README](../README.md#微信读书没有这本书怎么办)。
3. 明确确认一次，等待回读。同日小样本 13 秒在书城版实际到账，进度未被试传改变。随后书城和个人导入书均出现过部分到账，也出现过同书多次分批后 `succ=1` 但统计无增长。
4. 账本先登记再发送一次，最多做 8 轮只读回查。对于 `needs_review` 或 `unknown` 保留原账本和回执。已确认、待核验的源日志都留在同一实例，迁移到设备端时使用旧实例交接，禁止以新空账本重复提交。
5. 当前合并方式仍未验证能可靠补齐所有同书、跨日批次。仓库里的回归使用合成数据，不包含书名、账号、日志、二维码或私人账本。查看 [开发说明](DEVELOPMENT.md) 中的离线测试入口。
